# 段階 7：スナップショットの PoC

接続がなくなって止めるとき、VM をシャットダウンせずにスナップショットに取り、次の接続で戻せるかを確かめた（2026-10-17）。
結論として、当面は採らずにコールドブートを続ける。
採るときに必要なことは、最後の節にまとめる。

## 確かめ方

開発用のランナーのコンテナ（`run.sh`、NAT のモード、メモリ 1GiB、vCPU 4）で、次の順に行った。

1. VM を起動し、VM の中で `setsid` で常駐するプロセスを起こし、ワークスペースのディスクにファイルを書く。
2. Firecracker の API で `PATCH /vm`（`Paused`）と `PUT /snapshot/create`（`Full`）を送る。
3. コンテナを `docker rm -f` で消し、70 秒待つ。
4. 新しいコンテナを起動し、Firecracker を `--api-sock` だけで起動して `PUT /snapshot/load`（`resume_vm: true`）を送る。
5. guest-agent への接続、常駐するプロセス、ファイル、時刻、外への通信を確かめる。

エントリポイントは、次のように変えて確かめた（PoC のあとで戻した）。

- Firecracker を `--no-api` ではなく `--api-sock /state/firecracker.sock` で起動する。`--config-file` と一緒に使える。
- `/state/snapshot/` にスナップショットがあれば、起動せずにそこから戻す。
- tap0 の MAC を固定する（`ip link set tap0 address ...`）。コンテナを作り直すと tap の MAC が変わり、戻した VM の ARP のキャッシュが古いままになるためである。

## 結果

| 項目 | 結果 |
| --- | --- |
| コールドブート（guest-agent が答えるまで） | 2.9 秒 |
| 一時停止とスナップショットの作成 | 1.4 秒 |
| スナップショットから戻す（guest-agent が答えるまで） | 0.8 秒 |
| メモリのファイル | 1GiB（メモリの大きさそのまま。疎なファイルにならない） |
| 状態のファイル | 50KB |
| 常駐するプロセス | 戻したあとも同じプロセス ID で動いている |
| ワークスペースのファイル | 残っている |
| guest-agent（vsock） | 戻したあとにつながる。スナップショットの前の接続は切れる |
| 外への通信（DNS と HTTPS） | 戻したあとも通る（tap の MAC を固定した場合） |
| ゲストの時刻 | スナップショットを取った時刻のまま進まない（70 秒待って 73 秒遅れていた） |

## 当面は採らない理由

- **コールドブートが十分に速い**：2.9 秒で guest-agent が答える。戻すのとの差は約 2 秒で、接続のたびに待つ時間として困るほどではない。
- **ワークスペースごとにメモリの大きさのファイルが要る**：メモリ 4GiB のワークスペースなら、止めているあいだも 4GiB のディスクを使う。利用者の数だけ積み上がる。
- **時刻を直す仕組みが要る**：戻した VM の時刻は止めたときのままである。プロキシはその時点の時刻で証明書を出すので、ゲストの時刻が遅れていると TLS の検証に失敗しうる。戻した直後に controller から時刻を送ってゲストで設定する、などの仕組みが要る。
- **作業中のエージェントは、すでに待ってから止めている**：止めて困る作業（エージェントのターン）は、段階 7 の作業待ちの停止で守っている。止めたときに失われるのは、VM の中で動かしたままのプロセス（開発用のサーバー、tmux のセッション）であり、ワークスペースとホームディレクトリのファイルは残る。

## 採るときに要ること

- 接続がなくなって止めるときだけスナップショットに取り、`chloe ws stop` は本当にシャットダウンしてスナップショットを消す（プレースホルダーを入れ直すには、作り直しが要るため）。
- ルートのイメージ、カーネル、Firecracker の版、設定用ドライブの中身（プレースホルダー、ルートの扱い）が、スナップショットを取ったときと違えば、スナップショットを捨ててコールドブートする。
- スナップショットのファイルは一時的な名前で書き、書き終えてから名前を変える（途中で落ちても、壊れたスナップショットから戻さない）。
- 戻した直後に、ゲストの時刻を合わせる。
- メモリのファイルの置き場所と、使わなくなったスナップショットを消す期限を決める。
